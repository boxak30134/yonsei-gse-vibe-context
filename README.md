# 🦅 연세대학교 교육대학원 바이브 코딩 컨텍스트 (`yonsei-gse-vibe-context`)

연세대학교 교육대학원 원우들이 교육 현장용 웹 애플리케이션을 AI 코딩 에이전트(Claude Code, Cursor, Antigravity 등)와 함께 개발할 때, **코드 파괴와 토큰 낭비를 막고 전공 간 기술 노하우를 공유하기 위한 공동 지침 저장소**입니다.

---

## ✨ 이 컨텍스트를 쓰면 무엇이 좋아지나요?

1. **막막함 없는 3단계 기획 시작 (`/onboarding`)**: 빈 화면에서 무엇부터 지시할지 고민할 필요 없이, AI가 목적·핵심 기능·사용 기기를 차례로 묻고 개발을 시작합니다.
2. **교육 현장 특화 함정 자동 방어**: 한글 입력기(IME) 엔터 중복 실행, 학교 공공데이터(`CP949`) 인코딩 깨짐, 태블릿 가상 키보드 레이아웃 붕괴, API 키 유출을 사전에 차단합니다.
3. **토큰 및 API 비용 절약**: 불필요한 대용량 파일 전체 읽기를 금지하고, 작업 난이도와 현재 선택된 AI 모델 등급이 맞지 않으면 먼저 경고를 띄워줍니다.
4. **지식 환원 파이프라인 (`/report`)**: 개발 중 해결한 기술적 시행착오를 개인 코드는 쏙 빼고 중앙 저장소에 Pull Request(PR)로 간편하게 공유할 수 있습니다.

---

## 🚀 1분 만에 시작하기 (원클릭 초기 세팅)

> **사전 준비**: 내 PC에 `Git`이 설치되어 있어야 하며, AI 코딩 에이전트(Antigravity, Claude Code, Cursor 등)에서 **새 프로젝트 폴더**를 연 상태에서 진행해 주세요.

아래 회색 박스의 내용을 복사해 **AI 에이전트 채팅창에 그대로 붙여넣고 엔터**를 누르세요. 폴더 연결부터 초기 기획 질문까지 자동으로 시작됩니다.

```text
연세대학교 교육대학원 바이브 코딩 환경을 초기 세팅해 줘. 아래 작업을 순서대로 실행해:

1. 현재 프로젝트 루트에 `git clone https://github.com/boxak30134/yonsei-gse-vibe-context.git vibe-context` 명령으로 공유 컨텍스트 저장소를 내려받아 줘.
2. 루트의 `.gitignore` 파일(없으면 새로 생성)에 `vibe-context/` 와 `.env*` 두 줄이 포함되어 있는지 확인하고 없으면 추가해 줘.
3. 프로젝트 루트에 `AGENTS.md` 와 `CLAUDE.md` 두 파일을 생성하고, 둘 다 아래 내용을 똑같이 적어 줘:
@vibe-context/AGENTS.md

> **[시스템 지시]** 이 프로젝트의 모든 코딩 규칙과 작업 지침은 `vibe-context/AGENTS.md`에 정의되어 있습니다. 사용자의 요청을 처리하기 전에 반드시 `vibe-context/AGENTS.md` 파일을 먼저 읽고 지침을 따르세요.

4. 루트에 `.claude/commands/onboarding.md` 와 `.claude/commands/report.md` 파일을 생성해 줘:
   - `onboarding.md`: `vibe-context/AGENTS.md`의 0번 초기 온보딩 규칙을 실행하라는 지시문 연결
   - `report.md`: `vibe-context/AGENTS.md`의 6번 리포트 PR 파이프라인을 실행하라는 지시문 연결
5. 위 세팅이 끝나면 바로 `vibe-context/AGENTS.md`를 읽고 `/onboarding`의 첫 번째 질문을 나에게 던져 줘.
```

## 💡 일상 개발 치트시트 (자주 쓰는 명령어)

| 하고 싶은 작업 | 채팅창에 입력할 말 | 설명 |
| :--- | :--- | :--- |
| **새 앱 기획 시작** | `/onboarding` | 목적 → 핵심 기능 → 사용 기기 3단계 질문 후 개발 착수 |
| **최신 지침 업데이트** | `"컨텍스트 최신화해 줘"` | 공유 저장소의 최신 규칙과 전공별 패턴을 안전하게 동기화 |
| **트러블슈팅 공유** | `"응"` (에이전트 제안 시) 또는 `/report` | 개인 로직·API 키를 제거하고 해결 패턴만 중앙 저장소에 PR 생성 |
| **계획 생략 즉시 수정** | `"바로 구현해: [요청사항]"` | 3개 이상 파일 수정 시 거치는 사전 계획 승인을 건너뛰고 즉시 실행 |

## 🧠 토큰을 아끼는 AI 모델 선택 가이드

상황에 맞는 모델을 선택하면 사용량 한도(쿼터)를 아끼고 오류 루프를 줄일 수 있습니다.

* **고성능·추론 모델 권장** (`Claude Sonnet/Opus`, `Gemini Pro`, `GPT-4o/o3`)
  * 초기 기획(`/onboarding`), 전체 구조 설계, 3개 이상 파일 동시 수정, 원인을 알 수 없는 버그 해결
* **경량·속도 모델 권장** (`Claude Haiku`, `Gemini Flash`, `GPT-4o-mini`)
  * 버튼 색상·폰트·여백 수정, 오타 교정, 단일 파일 내 간단한 문구 변경

## 📂 저장소 폴더 구조

```text
yonsei-gse-vibe-context/
├── AGENTS.md                 # [마스터 지침] 온보딩·토큰절약·보안·Git 동기화 통합 규칙
├── CLAUDE.md                 # Claude Code 전용 진입점
├── rules/                    # 공통 보조 규칙 (한글 IME, 인코딩 안전 수칙 등)
├── patterns/                 # 전공 횡단 공통 기술 패턴 (이중 캔버스 필기, 무과금 BYOK API, PPTX 내보내기 등)
├── majors/                   # 교과 고유 도메인 제약 지침 (수학교육 KaTeX·좌표계, 어학교육 루비 태그 등)
└── community-reports/        # 원우들이 직접 기여한 실전 트러블슈팅 리포트 모음
```

## 🤝 공동체 기여 안내 (Community Reports)

개발 도중 까다로운 에러를 해결하면 AI 에이전트가 완료 보고 하단에 다음과 같이 먼저 물어봅니다.

> 💡 방금 해결한 **[핵심 기술 키워드]** 패턴은 다른 원우들에게도 유용할 것 같습니다. 개인 코드는 빼고 공유 저장소에 리포트로 올릴까요? (`응` / `아니오`)

* **`"응"`**이라고 답하면 AI가 개인 앱 이름, API 키, 수업 데이터를 자동으로 삭제한 뒤 중복 문서를 확인하여 Pull Request를 생성합니다.
* GitHub CLI(`gh`)가 설치되지 않은 PC에서도 로컬 리포트 파일이 자동 생성되므로, 해당 파일을 GitHub 웹사이트에서 간편하게 업로드하실 수 있습니다.
